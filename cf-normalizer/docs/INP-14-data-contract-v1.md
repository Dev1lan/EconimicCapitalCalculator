# Контракт данных CF Normalizer v1.0.0

Нормализатор принимает банковский CSV и формирует данные для C++-ядра `cfcore`. Состав и порядок 29 выходных полей определены [JSON-схемой](../contracts/normalized-deals-v1.json).

Совместимость проверена с [`Dev1lan/EconimicCapitalCalculator`, ветка `develop/core`](https://github.com/Dev1lan/EconimicCapitalCalculator/tree/develop/core), коммит `6fa3b5c`.

## 1. Входной CSV

- Кодировка UTF-8 (BOM допустим); разделитель `;`; первая строка — заголовок.
- Все значения читаются как строки; пустые ячейки — `null`. Дополнительные колонки допускаются.
- Обязательные колонки: `deal_id`, `report_dttm`, `discriminator`, `currency_id`, `current_principal_amt`, `deal_dttm`, `maturity_dttm`, `rate_type_cd`, `interest_rate`, `day_convention_cd`.
- Отсутствующая обязательная колонка — ошибка файла; пустое значение в ней — карантин строки.
- Даты: `DD.MM.YYYY` или `YYYY-MM-DD`. Числа: десятичная точка; ставки задаются долями (`0.075` = 7,5%).
- `discriminator`: `ANN`, `RGM`, `SIMPLE`. `rate_type_cd`: `FIXED`, `FLOAT`.
- Валюта версии 1: только `RUB`. Сделки с непустыми полями `sub_*` не поддерживаются.

## 2. Выходные файлы

| Файл | Формат |
|---|---|
| `normalized_deals.csv` | UTF-8 без BOM, `;`, 29 колонок в порядке JSON-схемы, даты `YYYY-MM-DD`, пустые необязательные поля — пустые ячейки |
| `normalized_deals.parquet` | Те же 29 колонок; `int64`, `int32`, `float64`, `date32`, `utf8`; отсутствующие значения — Arrow `null` |
| `quarantine.csv` | UTF-8, разделитель `,`, колонки `deal_id,reason_code` |

Списки в обоих форматах остаются строками:

- `interest_payment` и `repricing_dttm_schedule`: `YYYY-MM-DD YYYY-MM-DD`.
- `principal_payment`: `YYYY-MM-DD,сумма YYYY-MM-DD,сумма`.
- `repricing_dttm_rate_schedule_fixed`: `YYYY-MM-DD,ставка YYYY-MM-DD,ставка`.

Списки сортируются по дате; повторяющиеся и прошедшие даты сохраняются. Числа не округляются, `NaN` и `Inf` недопустимы. Числовой ноль не заменяется на пустоту.

## 3. Правила нормализации

| Поле | Правило |
|---|---|
| `deal_id` | Уникальный `int64` |
| `side` | Отрицательный исходный остаток → `LIABILITY`, положительный → `ASSET` |
| `current_principal_amt` | Модуль исходного остатка, строго больше нуля |
| `portfolio_key` | Индекс пары (`product`, `behavior_model_cd`) с нуля; порядок первого появления среди принятых сделок; `product` со значением `product` считается пустым |
| `day_convention_cd` | `ACT/365` → `ACT_365`; `ACT/ACT` и `ACT/ACT ISDA` → `ACT_ACT_ISDA` |
| `interest_rate` | `FIXED`: неотрицательная ставка; `FLOAT`: допускается отрицательный спред |
| `base_indicator_rate` | При внешних `--fixings` для `FLOAT` — пусто; без `--fixings` — значение источника |
| `maturity_dttm` | Строго позже `report_dttm` |

Даты должны быть календарно корректными и попадать в диапазон 1900-01-01 — 2200-01-01. При наличии обеих границ ставки `floor_limit_interest_rate` не может превышать `cap_limit_interest_rate`.

Правила платежей (`interest_payment_rule_*`, `regular_payment_rule_*`, `repricing_rule_*`):

- `period_cd`: пусто, `ENDDATE` или положительное число с суффиксом `M`/`D` (`1M`, `45D`).
- `day_num`: `0..31`; для `repricing_rule_day_num` также `-1`.
- Пустой `day_num` интерпретируется ядром как `0`. При пустом `period_cd` ядро игнорирует `start_dttm` и `day_num`.

## 4. Ошибки

Ошибки отсутствия файла, повреждения CSV, отсутствия обязательной колонки или повторения имени колонки останавливают обработку.

Невалидные строки не передаются ядру и записываются в `quarantine.csv` в порядке исходных строк:

| `reason_code` | Условие |
|---|---|
| `UNSUPPORTED_CURRENCY` | Валюта не `RUB` |
| `SUB_BLOCK_UNSUPPORTED` | Заполнено поле `sub_*` |
| `MISSING_REQUIRED` | Пустое обязательное значение |
| `INVALID_ID` | Некорректный или повторяющийся `deal_id` |
| `INVALID_ENUM` | Недопустимый код графика, ставки или конвенции |
| `INVALID_DATE` | Недопустимая дата или дата погашения |
| `INVALID_NUMBER` | Недопустимое числовое значение |
| `INVALID_RULE` | Недопустимый период или день правила |
| `INVALID_SCHEDULE` | Некорректный список дат или пар |

При нескольких ошибках используется первый код из таблицы.

## 5. Граница ответственности

Нормализатор проверяет и преобразует входные значения, но не рассчитывает графики и денежные потоки. Проверки сумм графиков, доступности ставки и результаты расчёта относятся к `cfcore`. Например, `SCHEDULE_SUM_MISMATCH` сделки №20 — ошибка ядра, а не карантина.

`cfcore` принимает `normalized_deals.csv`; прямое чтение Parquet ядром не реализовано.

Требуют методического подтверждения: определение `side` по знаку остатка, формирование `portfolio_key` по порядку появления и интерпретация `FLOAT` как индикатора со спредом.
