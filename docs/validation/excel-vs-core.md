# Независимая сверка C++ Cash Flow Engine с Excel

Ветка **release/cf-core-final-validation**, коммит **c1a9e0b**. Сделка № 1 прошла Python-нормализацию и расчёт C++ во всех трёх политиках на Windows.

- **LEGACY_EXCEL** воспроизводит 334 даты, бакеты и все четыре денежные величины до копейки. Максимальная ошибка до округления — 8,331 × 10⁻⁸ ₽ по остатку.
- **BASE** совпадает по датам и бакетам. ACT/ACT ISDA меняет разбивку платежей с января 2024 года. Погашение остатка меняет последний общий платёж на 1 195,82 ₽.
- **CONTRACTUAL_V2** воспроизводит 334 плановые даты и их бакеты. Денежный вывод содержит 332 даты. Долг погашается 22.04.2050, и два последующих события графика дают нулевой поток.

[Построчная сверка](excel-vs-core.csv) содержит 334 строки данных, исходные значения, результаты и разницы каждой политики. Для импорта CSV используйте UTF-8, запятую как разделитель полей и точку как десятичный разделитель.

## Источник и независимость расчёта

Книга «Расчеты_Analytics_1 сделка.xlsx». SHA-256 45089d669322a53dfc6fdcb866836fe711aaced60c1acc6dde6ceff4386d9397.

| Область листа «1 сделка» | Что использовано |
| --- | --- |
| Строки 1 и 3 | Сделка № 1, ANN, FIXED, RUB, текущий долг 3 646 037,89 ₽, ставка 7,5%, начало 22.06.2020, отчётная дата 31.08.2022, погашение 15.06.2050. Правило 1M отсчитывается от 22.06.2020. Day count в карточке ACT/ACT, значение accrued_interest пустое. |
| B14, B15, B17 | Аннуитетный платёж 26 037,32199991525 ₽, число платежей 334, предыдущая купонная дата 22.08.2022. |
| B19:I352 | B — даты, D — погашение долга, E — остаток, F — проценты, G — общий платёж, H — дни от отчётной даты, I — бакет. |
| B5:U11 | Метки, теноры и коэффициенты дисконтирования. Столбец H пуст в таблице бакетов. |

Банковский CSV для нормализатора собран из **карточки сделки** по схеме [test_deals_mai.csv](../../data/input/test_deals_mai.csv). Даты платежей, суммы, остатки и бакеты из Excel использовались только на стороне сравнения. C++ построил график по периодичности 1M и дате окончания договора.

В B14 месячная ставка равна J3 × 0,0833333333333333. Формула F19 считает проценты как F3 × J3 × (B19 − B17) / 365. Далее книга берёт остаток из предыдущей строки и делит фактические дни на 365, включая високосные периоды. Principal равен B14 минус проценты. Остаток уменьшается на principal. Платёж в G равен сумме долга и процентов. На последней дате применяется тот же шаблон. Независимый пересчёт формул десятичной арифметикой по условиям и датам книги дал максимальное отклонение от сохранённых результатов 8,39 × 10⁻⁸ ₽.

## Сопоставление и допуски

- Выход C++ сгруппирован по сделке, дате и типу строки. Principal и interest сложены в общий платёж. Остаток взят после события PRINCIPAL из трассы.
- До округления использованы сохранённые значения из XML книги и значения трассы C++ с точностью до 17 значащих цифр. Principal и interest из трассы дополнительно сверены с опубликованным денежным CSV. Порог несовпадения — строго больше 0,000001 ₽, как в golden-тесте. Суммы учитывают и отклонения меньше порога.
- Отображаемые суммы сравнивались после округления до 0,01 ₽ по формату D:G. Допуск нулевой. Общий платёж округлён после сложения исходных компонент, как в формуле G. Отдельный запуск нативного CLI с --round-money подтвердил копейки по каждой опубликованной строке principal и interest.
- Разница рассчитана как C++ минус Excel. Для остатка суммы отклонений считаются по всем датам и служат диагностикой.

## Проверка golden-тестов

- В deal1_flows.csv совпали даты и бакеты всех 334 строк сделки № 1. Максимальная ошибка к книге составила 2 × 10⁻¹² ₽ по principal, 2 × 10⁻¹² ₽ по interest и 2 × 10⁻¹⁰ ₽ по остатку. Прямое сравнение подтверждает соответствие содержимого предоставленной книге. История происхождения файла отдельно не установлена. [Фикстура потоков](../../data/golden/deal1_flows.csv)

- Golden-тест проверяет даты, бакеты, компоненты платежа и остаток в LEGACY_EXCEL. Независимая сверка охватывает также общий платёж, копейки и ввод через нормализатор. Все три теста Golden прошли в нативной сборке Windows. [Тесты](../../core/tests/test_golden.cpp#L54)

## Граница проверки CF

Проверены недисконтированные потоки, остатки и распределение по времени. Значения NPV в книге — 2 056 999,50 ₽ для базового сценария и 1 892 477,08 ₽ для стрессового. ΔNPV — −164 522,41 ₽ (K353, M353, N353). Коэффициенты даны в книге. Golden-тест умножает потоки на DF из фикстуры в коде теста. Построение внешних кривых, дисконтирование в рабочем конвейере и экономический капитал лежат за пределами этой проверки. Лист «Портфель 5 сделок» содержит ошибки ссылок по другим сделкам. Проверка ограничена сделкой № 1.

## Воспроизведение

Из корня рабочего дерева. Подготовить deal-from-xlsx.csv из карточки по правилам выше. Указать путь к собранному cfcore.exe. Нормализатор создаёт нормализованные входы, запускает C++ и сохраняет результаты в подпапке core.

```powershell
$env:PYTHONPATH = (Resolve-Path cf-normalizer/src).Path
$cfcore = '.\build\core\cfcore.exe'
foreach ($mode in @('legacy-excel', 'base', 'contractual-v2')) {
    python -m normalizer deal-from-xlsx.csv --output-dir "audit/$mode" --format csv --cfcore $cfcore --policy $mode --threads 1 --events --trace-deal 1
}
```
